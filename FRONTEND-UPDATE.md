# Обновление frontend: логотип, ЧаВо и темы

## Установка

1. Остановите frontend через Ctrl+C в его окне.
2. Из корня вашего Git-репозитория создайте ветку: `git switch -c feature/frontend-polish`.
3. Сохраните резервную копию текущей папки FRONTEND.
4. Распакуйте архив в корень проекта — туда, где находятся FRONTEND, Obninsk_Hakaton2 и Start-Frontend.cmd. Согласитесь заменить файлы. Папка FRONTEND из архива должна объединиться с существующей FRONTEND. Не распаковывайте архив внутрь FRONTEND: иначе получится лишний уровень вложенности.
5. Backend менять и миграции выполнять не нужно. База, сессии, роли и API сохранены.

Откройте PowerShell в корне репозитория:

```powershell
cd .\FRONTEND\my-volunteer-app
npm.cmd ci
npm.cmd run test:ui
npm.cmd run lint
npm.cmd run build
npm.cmd run dev
```

Для подключения с телефона вместо последней команды:

```powershell
npm.cmd run dev -- --host 0.0.0.0
```

Django должен быть запущен прежним способом. Настройки доступа по IP и брандмауэра остаются прежними. Можно также запускать frontend через Start-Frontend.cmd.

## Что изменено

- Общий компонент BrandLogo использует ваш public/logo.png во всех шапках React, в том числе на главной и регистрации. PNG также используется как иконка вкладки.
- Убраны статические пометки о деморежиме, прототипе и учебной выдаче из React-интерфейса. Названия событий и поощрений, а также основания старых операций приходят из базы без изменения; при необходимости их редактируют отдельно в Django Admin. Исторические операции не переписываются.
- На главной справа внизу кнопка «ЧаВо» открывает окно с 10 ответами по правилам приложения. Раскрытие вопроса — нажатием или клавиатурой. Закрытие — крестиком, Escape или нажатием на фон.
- Слева внизу всех React-страниц переключатель светлой/тёмной темы. Выбор сохраняется в localStorage только как настройка оформления, синхронизируется между вкладками; до первого выбора используется тема устройства. При загрузке страницы тема применяется до запуска React.
- Тёмная палитра охватывает формы, карточки, меню, таблицы/списки, статусы и диалоговые окна. Фирменные синие блоки и цвет логотипа сохранены.
- Django Admin — отдельный интерфейс Django с собственным оформлением; этот архив меняет React.

## Проверка вручную

1. На главной, регистрации и входе должен быть одинаковый настоящий логотип. В кабинетах он находится в общей шапке.
2. На главной откройте ЧаВо, раскройте вопрос о возврате, закройте окно. Проверьте Escape и навигацию Tab.
3. Переключите тему, перейдите на регистрацию и обратно, обновите страницу: выбранная тема сохраняется.
4. В обоих кабинетах проверьте поля, ошибки, карточки мероприятий, статусы и диалоги отчёта/обмена в обеих темах.
5. На телефоне проверьте кнопки темы и ЧаВо: они находятся с разных сторон внизу и доступны поверх страницы.
6. Проверьте обычный сценарий регистрации, отчёта, подтверждения и обмена на вашем Django.

## Автоматические проверки

`npm.cmd run test:ui` запускает 12 проверок в JSDOM: логотип и переключатель на 8 маршрутах, сохранение/инициализация/синхронизация темы, открытие и закрытие ЧаВо. API в этих проверках подменён фиксированными ответами, работа с реальным Django ими не проверяется. Также прошли ESLint и production-сборка.

Существующие `test:integration` и `test:e2e` сохранены. Для них нужен рабочий Django; в этой итерации они не запускались. Полную браузерную/визуальную проверку здесь выполнить не удалось: браузер Chromium не удалось установить. Проверьте отображение на вашем ПК и телефоне перед merge.

## Сохранить изменения в Git

После проверки вернитесь в корень репозитория:

```powershell
cd ..\..
git status
git add FRONTEND FRONTEND-UPDATE.md
git diff --cached --stat
git commit -m "Polish frontend branding, FAQ and light/dark themes"
git push -u origin feature/frontend-polish
```

Если ваша текущая интеграционная ветка ещё не в main, эта новая ветка содержит и её коммиты. Не сливайте два PR вслепую: либо обновите существующий PR через исходную ветку, либо сделайте один PR из новой ветки в main и проверьте весь diff. Не используйте force push.
