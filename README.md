# Цифровой волонтёр Обнинска

Общее приложение команды **team_escape**: **React + Tailwind CSS** отображает интерфейс, **Python/Django** хранит пользователей, мероприятия, отчёты, часы, койны и запросы на поощрения.

Сценарий: регистрация → мероприятие → запись → отчёт → проверка координатором → начисление койнов → учебная покупка. Вся информация сохраняется в SQLite, а не в браузерном списке пользователей.

## Быстрый запуск на Windows

Нужны Python 3.12+ и Node.js 22.12+ либо 24. Сначала остановите старые серверы, занимающие порты 8000 и 5173.

1. Откройте корень проекта — папку с этим README.
2. Запустите **Start-Backend.cmd**. Он создаст `.venv`, установит Django, применит миграции, подготовит учебные данные и запустит backend.
3. Запустите **Start-Frontend.cmd**. Он установит frontend-зависимости из lock-файла и запустит Vite.
4. Оба окна оставьте открытыми.
5. Откройте **http://127.0.0.1:5173/** — это адрес общего приложения.

Вместо двойного щелчка можно выполнить в двух терминалах PowerShell из корня проекта:

```powershell
.\Start-Backend.cmd
```

```powershell
.\Start-Frontend.cmd
```

Скрипты не требуют активации PowerShell-окружения. Для первоначальной установки зависимостей нужен интернет. Работа самого учебного приложения использует локальные Django и SQLite.

## Учебные аккаунты

| Роль | Логин | Пароль |
|---|---|---|
| Координатор | `coordinator` | `Demo-Obninsk-2026!` |
| Волонтёр | `volunteer` | `Demo-Obninsk-2026!` |

Вход: http://127.0.0.1:5173/login

Либо зарегистрируйте нового волонтёра через http://127.0.0.1:5173/volunteer. После регистрации откроется настоящий каталог мероприятий. Аккаунты из прежнего `localStorage`-макета не являются пользователями Django; создайте профиль в новой форме. Пароли в браузере больше не сохраняются.

Координатору права назначает администратор. Публичная регистрация не позволяет получить роль координатора. Учебный координатор создаётся командой `seed_demo`; существующие пароли и права при повторном запуске не сбрасываются.

Панель координатора React: http://127.0.0.1:5173/coordinator-dashboard

Django Admin через тот же origin: http://127.0.0.1:5173/admin/

## Что подключено

- Регистрация с проверкой пароля, логина, телефона и необязательных контактных данных.
- Вход, выход и восстановление сессии после обновления страницы.
- Каталог мероприятий из БД и запись без дубликатов.
- Отчёт после окончания мероприятия: часы и описание.
- Проверка отчётов в React-панели координатора и Django Admin.
- Коэффициент от **1.00 до 10.00**, шаг **0.05**, по умолчанию **1.00**. При отличии от 1 нужна причина.
- Создание мероприятий из React-панели; редактирование ставок и дат в Django Admin.
- Общий баланс, подтверждённые часы и история операций.
- Реальный каталог учебных поощрений, подтверждение покупки и запрос на выдачу.
- Отметка условной выдачи координатором.
- Состояния загрузки, ошибки, повтор запросов и адаптивное оформление.

Макетные цифры на главной заменены статистикой сервера. Баланс в шапке, профиле и магазине берётся из одного источника.

## Начисление

```text
Койны = подтверждённые часы × ставка при записи × коэффициент
```

Примеры: **3 × 10 × 1.00 = 30**; **3 × 20 × 1.50 = 90**.

Расчёт выполняется на Django через Decimal с округлением ROUND_HALF_UP до целого койна. Ставка сохраняется при записи: изменение события не пересчитывает старые участия. Часы — 0.1–24 с шагом 0.1. Причина изменения коэффициента сохраняется вместе с решением.

Запись имеет статус `registered`. После отчёта — `pending`. Начисление происходит только при `approved`; отказ `rejected` требует причины. Пока отчёт не рассмотрен, волонтёр может его уточнить. Повторное подтверждение и изменение рассмотренного отчёта запрещены.

Форма открывается после `ends_at`; для прежних событий без окончания используется `starts_at`. `seed_demo` оставляет существующие события как есть, но при необходимости добавляет отдельное завершённое учебное событие для проверки отчётов.

## Магазин и единый баланс

Основной баланс — `accounts.VolunteerProfile.balance`. Все новые начисления и покупки проходят через `catalog/services.py`. Источник каждой операции связан с участием или запросом на поощрение.

Старые модели `shop.Profile`, `shop.Purchase`, `shop.Item` и `Person` сохранены. Старый независимый баланс не расходуется: `/shop/` ведёт в новый React-магазин. Архивные таблицы доступны суперпользователю только для просмотра. Новым пользователям больше не выдаются автоматические 100 монет старого магазина. Существующие архивные записи не удаляются и не добавляются к подтверждённому балансу.

Миграция переносит положительно оценённые позиции старого каталога в `catalog.Reward`. Для учебного магазина дополнительно создаются три стандартных поощрения.

Каждая покупка отправляет UUID намерения. При потере ответа клиент повторяет запрос с тем же UUID; повторное списание не происходит. Цена берётся с сервера, а остаток проверяется в БД.

## Как проверить вдвоём на одном ПК

1. В обычном окне зарегистрировать волонтёра и записаться на завершённое событие со ставкой 10.
2. Отправить отчёт на 3 часа. Баланс должен остаться нулевым.
3. В инкогнито открыть тот же адрес `127.0.0.1:5173`, войти координатором.
4. В «Отчётах» подтвердить 3 часа при коэффициенте 1.00.
5. Вернуться в окно волонтёра и нажать «Обновить», если данные ещё не обновились. Баланс — 30.
6. В «Поощрениях» обменять 20 койнов на значок. Остаток — 10.
7. В окне координатора открыть «Выдача поощрений» и отметить запрос.
8. Проверить повторное подтверждение: backend вернёт конфликт без начисления.

Дополнительно создайте завершённое событие со ставкой 20 и подтвердите 3 часа с коэффициентом 1.50 и причиной «Дождь»: начисление 90 койнов.

## Запуск вручную

Из корня проекта:

```bash
python -m venv .venv
```

Активируйте `.venv` своим способом (`.venv\Scripts\activate.bat` в Windows cmd или `source .venv/bin/activate` в Linux/macOS), затем:

```bash
python -m pip install -r requirements.txt
python Obninsk_Hakaton2/manage.py migrate
python Obninsk_Hakaton2/manage.py seed_demo
python Obninsk_Hakaton2/manage.py runserver 127.0.0.1:8000
```

В другом терминале:

```bash
cd FRONTEND/my-volunteer-app
npm ci
npm run dev
```

Frontend: **5173**, backend: **8000**. Vite проксирует `/api`, `/admin`, `/static`, `/accounts`, `/shop` в Django с сохранением Host. Cookie и CSRF работают на одном origin. Не смешивайте `localhost` и `127.0.0.1` в одной проверке.

Для проверки production-сборки:

```bash
npm run build
npm run preview
```

Preview работает на `http://127.0.0.1:4173/` и тоже использует работающий backend. `vite preview` предназначен для локальной проверки сборки, а не публичного размещения.

## Проверки

Из корня, с Python-зависимостями в активном окружении:

```bash
python Obninsk_Hakaton2/manage.py test accounts catalog shop --settings=Obninsk_Hakaton2.test_settings --noinput
python Obninsk_Hakaton2/manage.py check
python Obninsk_Hakaton2/manage.py makemigrations --check --dry-run
```

Frontend:

```bash
cd FRONTEND/my-volunteer-app
npm run lint
npm run build
npm run test:integration
```

`test:integration` требует запущенных Django на 8000 и Vite на 5173. Он запускает React в JSDOM, но запросы отправляет на настоящий сервер, с cookie и CSRF. Проверяет регистрацию, роли, отчёт, начисление 30, покупку за 20, остаток 10 и историю. Он создаёт отдельного учебного пользователя.

В архиве также есть браузерные Playwright-сценарии. При наличии браузера и работающих серверов:

```bash
npx playwright install chromium
npm run test:e2e
```

**Проверено при подготовке:** 59 backend-тестов, 2 интеграционных React-теста с настоящим Django, сборка и lint frontend. Миграции согласованы с моделями. В данной среде Chromium не запускается, поэтому полноценные браузерные сценарии и визуальная проверка не выполнены; JSDOM не заменяет проверку отображения в браузере.

## Обновление существующей базы

Миграции добавлены, база не включена в архив и не удаляется кодом. Существующие подтверждения, балансы и история сохраняются. Если раньше использовались миграции `catalog/0002_event_rates_and_reports` и `0003_multiplier_step`, их имена сохранены для совместимости.

Перед переносом в рабочий Git сохраните свои текущие изменения. Для первого запуска удобнее распаковать архив в отдельную папку и проверить на учебных данных. Для работы со своей базой перенесите изменения в существующую интеграционную ветку и выполните `migrate`; старые миграции удалять не нужно.

## Структура

```text
FRONTEND/my-volunteer-app/
  src/auth/                 — сессия и проверка входа
  src/lib/api.js            — JSON API, CSRF и ошибки
  src/lib/useResource.js    — загрузка и обновление данных
  src/*Dashboard.jsx        — каталоги и панель координатора
  tests/                    — DOM-интеграция и браузерные сценарии
Obninsk_Hakaton2/
  accounts/                 — регистрация, контакты и баланс
  catalog/                  — события, отчёты, награды, операции и API
  shop/                     — совместимость со старым магазином
  templates/                — вспомогательные Django-страницы
Start-Backend.cmd
Start-Frontend.cmd
```

Контракт API: [docs/API.md](docs/API.md).

Все пользователи, события и награды учебные. Койны не являются деньгами и не гарантируют настоящую награду. Публичное размещение требует отдельной настройки HTTPS, секретов, допустимых хостов и отказа от общих учебных паролей. Переменные Django: `DJANGO_SECRET_KEY`, `DJANGO_DEBUG`, `DJANGO_ALLOWED_HOSTS`, `FRONTEND_URL`; `.env` автоматически не загружается.

## Шаблоны и возвраты

Координатор сохраняет шаблоны на сервере и создаёт из них мероприятия с новыми датами. Из существующего мероприятия можно сохранить шаблон. Волонтёр и координатор могут отменить ожидающий выдачи запрос с однократным возвратом исходной цены; выданные запросы отменять нельзя. История сохраняет списание и возврат.

Установка обновления, публикация в GitHub и очистка веток: [UPDATE-TEMPLATES-REFUNDS.md](UPDATE-TEMPLATES-REFUNDS.md).
